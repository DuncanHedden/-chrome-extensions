Reading logs like a query

Every service writes a log. The log is the first place to look when something breaks, but a log is only useful if you can search it. Logging libraries add structure, and a catalog of log formats helps, yet most of the time you are scrolling a long page looking for one line.

Plain text search finds a word. A regular expression finds a shape: every date, every ticket ID, every line that starts with ERROR and mentions a timeout. That is the difference between reading a log and querying it.

Whole-word matching matters more than it sounds. Searching for "log" should not light up "logging", "catalog" or "blog". Wrapping the pattern in word boundaries fixes that, and the find bar does it with one toggle.

Case matters too. "Error" in a heading and "ERROR" in a log line are different things, and sometimes you want only one of them.
